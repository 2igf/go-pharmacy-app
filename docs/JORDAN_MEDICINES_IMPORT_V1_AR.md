# استيراد حزمة الأدوية الأردنية — تنفيذ واختبار V1

## النتيجة وحدودها

استُخدم مخطط Medication Knowledge Base القائم، دون إنشاء دليل موازٍ. استُوردت 1000 عبوة إلى قاعدة اختبار مستقلة وأصبحت قابلة للبحث والتصفح والتفاصيل في واجهة React المضمّنة داخل Android WebView. هذه معاينة داخلية لبيانات تاريخية غير مراجعة، وليست قائمة أدوية معتمدة حاليًا في الأردن أو معروضة للبيع.

- الفرع: `feat/jordan-medicines-dataset-v1`، من الأصل المحلي `548b537b92ead41093910cc54ef804be219c29b4` على `feat/go-pharmacy-customer-completion-v1`.
- لم يُعدّل main ولم يحدث دمج أو رفع أو نشر.
- لم يُتصل بقاعدة `go_pharmacy_phone_v2` أو Demo الأصلية، ولم تُعدّل خدماتهما أو نفق الهاتف.
- ملفات المصدر الكاملة والنصوص السريرية والاعتمادات محلية مستثناة من Git، وليست ضمن APK.

صلاحية رقم التحقق لا تثبت صحة ربط الباركود بالمنتج أو أصالة العبوة. ATC من المصدر فقط: قُبلت المستويات الهرمية الأقصر، ولا يُستنتج تحقق سريري من صحة الصيغة. لا تُدمج عبوات مختلفة لمجرد تشابه الاسم.

قورنت 38,038 خلية بين CSV وExcel. توجد 14 اختلافًا لفظيًا رقميًا متكافئًا، و51 فرق تمثيل عشري ناتجًا عن تسلسل أرقام Excel، بأقصى فرق مطلق 1e-13. لا فرق مادي تحت حد المقارنة المعلن 1e-12. لم تُبدّل قيم CSV بقيم Excel. لا صيغ أو خلايا إضافية غير فارغة خارج النطاق على ورقة المنتجات.

الفحص النهائي يسجل **140 صفًا بها تحذير واحد أو أكثر**: 119 باركودًا مفقودًا، 4 معرّفات غير GTIN، 2 checksum غير صالح، 3 ATC مفقودة، 22 قيمة ATC قُصّت مسافاتها الخارجية، وتركيز واحد مفقود. قد تتداخل التحذيرات على الصف نفسه. التقرير الأول احتوى تحذيرات أولية زائدة لأكواد ATC الهرمية الأقصر؛ المرجع النهائي للتحذيرات هو `import-final-repeat.json` بعد تصحيح تصنيف المستويات. لم يغيّر هذا قيم الأدوية أو هويتها.

أمثلة تحذيرات تستلزم مراجعة المصدر:

- تركيز مفقود: JO-MED-0761.
- checksum غير صالح: JO-MED-0186 وJO-MED-0927؛ حُفظت القيمة الأصلية مع حالتها ولم تُصلح بالتخمين.
- معرّفات غير GTIN: JO-MED-0089 وJO-MED-0127 وJO-MED-0662 وJO-MED-0664.
- ATC مفقود: JO-MED-0111 وJO-MED-0147 وJO-MED-0293.

كل صف مرفوض كان سيُسجّل برقم الصف وproduct_id وأسباب الرفض؛ لا رفض في الحزمة الفعلية. القوائم الكاملة والتحقق الرقمي والتجزئات في `evidence/jordan-import/validation.json` و`import-final-repeat.json`.

## ربط الحقول بالمخطط الموجود

| المصدر | التخزين / الحدّ |
|---|---|
| product_id | knowledgeDrugs.externalId تحت مصدر مستقل jordan_package_2021؛ القيد الفريد الحالي sourceId + externalId |
| trade_name / generic_name | knowledgeNames مع kind وlanguage؛ الأسماء الإنجليزية لا تُترجم تلقائيًا |
| generic_name / strength | knowledgeIngredients وknowledgeDrugIngredients.strength؛ لا تقسيم تخميني للمركبات، والتركيز المفقود null |
| dosage_form / route | knowledgeProductFacts؛ النص كما ورد |
| barcode / ATC / category / package_size | catalogMetadata مع حالة فحص الباركود؛ ليست إثباتات تنظيمية |
| manufacturer_or_agent_ar/en | supplierAr/supplierEn؛ manufacturer يبقى null لأن الطرف قد يكون مورّدًا أو وكيلًا |
| أسعار 2021 | publicPriceHistoricalJod/hospitalPriceHistoricalJod داخل metadata؛ لا officialMedicinePrices ولا سعر متجر أو تسجيل حالي |
| source_date / last_checked / URLs | تواريخ وروابط المصدر الأصلية، مع توضيح أنها ادعاءات المصدر وليست تحققًا مستقلًا |
| حالات التحقق والوصفة والتوفر وعضوية القوائم | ادعاءات المصدر محفوظة مع review=unreviewed وregistration=unverified وreuse=pending؛ لا تحويل إلى OTC أو Prescription موثقة |
| clinical_source_url / clinical_label_date | روابط وتاريخ وصفيان فقط، دون نسخ النص السريري |
| نصوص الاستعمال والجرعة والتحذيرات والمحتوى العربي المشتق | مستبعدة من الاستيراد ومن label sections؛ محفوظة فقط في الأرشيف الأصلي المحلي |
| jfda_item_code والترجمة التصنيفية وبقية ملاحظات المصدر | تبقى في CSV الأصلي ذي التجزئة الثابتة؛ لا يُحوّل كود القائمة إلى registrationNumber |

يحمل كل سجل rowSha256 للصف الأصلي، ويحمل كل import batch تجزئة CSV كنسخة مصدر، وpermissionReference يوضح أن الاستخدام تقييم محلي فقط. لم تُنشأ صور أو أسعار مفقودة أو بيانات طبية بديلة.

## التصميم والأمان

الترحيل الإضافي `0010_jordan_catalog.sql` يضيف عمود JSON nullable إلى knowledgeProductFacts ومصدرًا إلى knowledgeSources. لا جدول أعمال جديد، ولا تعديلات على جداول المستخدمين والطلبات والمخزون. تستخدم العلاقات والفهارس والقيود الحالية، وتُحفظ metadata ضمن snapshots الحالية لاسترجاع الدفعات.

الاستيراد يستخدم `applyKnowledgeImport` نفسه بحد 10 سجلات لكل معاملة، مع تحقق دور admin من قاعدة البيانات وقفل المصدر. لا mutation عامة جديدة. يتخطى تطابق content hash، ويمنع استبدال عبوة موجودة مختلفة تلقائيًا عبر CONFLICT. يعالج الطلب المتكرر بالـrequestId ويحفظ التدقيق ونسخ السجلات. لا دمج تجاري عبر الاسم أو السعر.

الدليل يعيد استخدام `medicationKnowledge.search` و`medicationKnowledge.detail`. أُضيف النطاق `historical_jo` منفصلًا عن `JO` الموثق و`international`. البحث يشمل الاسم التجاري والعلمي والمادة، ومعرّف المصدر والباركود وATC، مع offset/limit وترتيب ثابت. تعرض بطاقة كل نتيجة تاريخية معرّف العبوة بالمصدر لتمييز العبوات التي تتشارك الاسم التجاري نفسه. حد الصفحة في العميل 20؛ لا اقتصار على أول 100. بحث substring الحالي مناسب لحجم الحزمة، وليس فهرس بحث متخصصًا لملايين السجلات.

المعاينة لا تعمل إلا عند اجتماع:

```
NODE_ENV=test # أو development
HISTORICAL_KNOWLEDGE_PREVIEW_ENABLED=true
```

في production يبقى المصدر غير متاح حتى لو ضُبط العلم true. كما يُمنع الوصول المباشر للتفاصيل عند إغلاق المعاينة. هذا قيد حقوق ومراجعة صريح؛ لا تفعّله بتغيير بيئة خدمة الهاتف خلسة.

واجهة التفاصيل توضح عدم توثيق التسجيل والوصفة والتوفر والمراجعة الطبية، وتعرض المصادر والتواريخ والهوية والتركيز وحالة الباركود. لا مبالغ أسعار تاريخية في واجهة العميل، ولا زر شراء أو تحويل إلى السلة. لم تُنشر label sections أو تسجيلات أردنية لهذه الحزمة.

## قواعد الاختبار وحماية البيانات

على مثيل MySQL المحلي المعزول الموجود سابقًا، منفذ 33318:

- `go_pharmacy_test_jordan`: نسخة مستقلة من `go_pharmacy_test_completion`، وهي بيانات خيالية للاختبار فقط؛ أضيف إليها المصدر و1000 سجل.
- `go_pharmacy_test_jordanreg`: قاعدة اختبارات إتلافية مستقلة لتشغيل fixtures، لا قاعدة العرض ولا الهاتف.

نُسخت 42 طاولة من بيئة الاختبار بقراءة snapshot وأخذ DDL والصفوف، ثم أُعيد بناؤها في القاعدة الجديدة مع تفعيل المفاتيح الأجنبية. النسخة المحلية قبل الترحيل في `.local/jordan/pre-migration.json`، وتجزئتها في `database-clone.json`؛ تحتوي بيانات اختبار واعتمادات خيالية، لذا لا تُرفع إلى Git. تؤكد `preservation.json` تطابق جميع الصفوف السابقة وأعداد جداول الأعمال، بما فيها سجلات المعرفة الاثنا عشر السابقة. أُضيف ترحيل واحد فقط إلى نسخة العرض، وطُبّقت سلسلة الترحيلات على قاعدة الاختبارات الفارغة.

### إعادة التشغيل الآمن على بيئة الاختبار الحالية

لا تطبع DATABASE_URL. حمّل سر الاختبار محليًا إلى متغير البيئة عبر ملف الخاص بالمشغل. يجب أن يطابق الهدف اسم القاعدة أعلاه، وأن يكون loopback. قبل DDL:

1. أوقف كتابات بيئة الاختبار المراد ترحيلها فقط.
2. تحقّق من الهوية الفعلية `SELECT DATABASE()`، وإصدار MySQL8، وتاريخ الترحيلات ومفاتيح FK، وشغّل preflight.
3. خذ نسخة احتياطية كاملة مشفرة أو محمية من DDL والبيانات والتدقيق، واختبر استعادتها في قاعدة أخرى مستقلة. احتفظ بتجزئتها وتاريخها.
4. اضبط MIGRATION_EXPECTED_DATABASE للاسم نفسه وشغّل `scripts/migrate.ts`. preflight يرفض عمودًا/مصدرًا غير مسجلين أو تطبيقًا جزئيًا بدل التخمين.
5. شغّل محليًا بواسطة tsx: `scripts/import-jordan-catalog.ts <CSV> <new-report.json>`، مع NODE_ENV=test وعلم المعاينة؛ الأداة محصورة بقاعدة go_pharmacy_test_jordan ومدير الاختبار المخزّن.
6. راجع applied/skipped/rejected والتحذيرات. كرّر بتقرير جديد للتحقق من skipped=1000، ثم اختبر البحث والتفاصيل.

العمليات DDL في MySQL لا تُعد معاملة ذرية كاملة. إذا انقطع الترحيل بين ALTER وINSERT، فلا تحذف العمود أو تعدّل journal عشوائيًا؛ أوقف القاعدة المتأثرة وشخّصها وقارن بالنسخة، واستعد النسخة إلى قاعدة جديدة قبل قرار الاستكمال. تبقى قاعدة المصدر دون تغيير.

للتراجع عن البيانات الجديدة: أغلق علم المعاينة أولًا، وراجع batchIds في `import-first.json`، واستخدم rollback الحالي بصلاحية admin للدفعات الأصلية بترتيب عكسي بعد التحقق من عدم وجود نسخ أحدث. التراجع يبقي سجلات التدقيق ويجعل الصفوف الجديدة removed، ولا يحذف سجلات المصدر أو المعرفة السابقة. التراجع عن DDL عادة غير مطلوب؛ لا تسقط العمود وفيه بيانات. لا تُجرى هذه الخطوات على الهاتف دون موافقة.

## المصادر وحقوق الاستخدام

صفحة [أسعار الأدوية الحكومية 2021](https://opendata.gov.jo/en/dataset/drug-prices-838-2021) تنسب المجموعة إلى JFDA وتسمي الترخيص Open Jordonian License. تحديث صفحة النشر لا يجعل أسعار 2021 أسعارًا حالية. صفحة [ترخيص البيانات الحكومية الأردنية](https://opendata.gov.jo/en/pages/jordanian-open-government-data-license) المسترجعة لم تُظهر نص الشروط الكامل؛ لذلك لم يُعلن اكتمال تصريح إعادة الاستخدام أو إعادة توزيع الحزمة.

README يذكر نصوص DailyMed مشتقة بحسب المادة مع محتوى عربي أولي. لا يوجد في الحزمة إثبات ترخيص شامل أو مراجعة سريرية للمنتج الأردني المحدد. يوجد تعارض صيغة ملحوظ في JO-MED-0001، و11 ادعاء بوجود label لا يحمل رابط label. لذلك استُبعدت جميع النصوص السريرية بدل نشرها اعتمادًا على هذا الوصف. روابط [DailyMed](https://dailymed.nlm.nih.gov/dailymed/about-dailymed.cfm) لا تعني اعتماد المنتج في الأردن.

قبل أي إتاحة عامة: احتفظ بنسخة شروط الترخيص الفعلية، وثّق الإسناد ونطاق إعادة الاستخدام وأي حقوق لطرف ثالث، ثم اطلب مراجعة مهنية للمحتوى السريري إذا أُريد نشره مستقبلًا. لا تُستنتج وصفة أو تسجيل حالي أو صورة مرخصة من وجود السجل.

## Android والتجربة المحلية

APK: `android/app/build/outputs/apk/debug/app-debug.apk`، الإصدار **1.1.0-beta.6**، versionCode **6**، الحزمة `com.gopharmacy.beta`. توقيع debug مطابق لملف beta.4 السابق المحفوظ محليًا، وفق المقارنة في `prior-apk-signature.txt` و`apk-signature.txt`. لم يُقرأ توقيع النسخة المثبتة على الهاتف في هذه المرحلة. فُحص تطابق 46 ملفًا مضمّنًا وعدم وجود server.url أو CA اختباري في APK العادي، مع تعطيل cleartext وmixed content.

لم يُثبّت هذا APK على الهاتف. تطبيق الاختبار داخل المحاكي حزمة منفصلة `.checkouttest`؛ الثقة بشهادة الاختبار تخص هذه الحزمة فقط. خدمة العرض TLS على loopback3451، ويصلها المحاكي عبر `https://10.0.2.2:3451`. لا يُستخدم هذا العنوان على الهاتف ولا يُنشر خارجيًا. إعدادات الهاتف الحالية لا تتغير عند بناء APK.

اختبار الدليل في البيئة المعزولة:

1. افتح تطبيق checkoutTest على المحاكي، المحمّل بـfixture الاختبار المحلي، واتصل بعنوان بيئة المحاكي أعلاه.
2. افتح دليل معلومات الأدوية من المنتجات أو `/medicines`.
3. اختر «كتالوج عبوات أردني تاريخي — قيد المراجعة».
4. تنقّل بين الصفحات؛ تحقق من 20 نتيجة في الصفحة 50، وصفحة 51 خالية.
5. ابحث عن ARICEPT ثم DONEPEZIL ثم 4714534315122 ثم N06DA02.
6. افتح Aricept Tab. وتحقق من JO-MED-0002 والباركود وATC والمصدر والتواريخ والتحذيرات. لا شراء ولا سعر حالي أو توصيات جرعات.
7. جرّب الباركودين المعلّمين غير صالحين، والتركيز المفقود، وتحقق من ظهور القيم الأصلية والحدود بوضوح.
8. غيّر النطاق إلى الأردن الموثق؛ لا ينبغي أن تظهر العبوات التاريخية فيه، ولا أن تُستبدل مصطلحات RxNorm الدولية السابقة.

## النقل اللاحق إلى قاعدة الهاتف — يتطلب موافقة منفصلة

لم يُنفذ نقل إلى قاعدة الهاتف. تثبيت APK وحده لا ينقل بيانات MySQL أو يضيف الدعم إلى backend القديم. بعد مراجعة الحقوق وموافقتك الصريحة:

1. وثّق نسخة خدمة الهاتف الحالية والمخطط والبيانات، وخذ backup واختبر استعادة مستقلة دون تغيير الخدمة الحالية.
2. أنشئ candidate مستقلة من قاعدة الهاتف؛ لا تنسخ حسابات أو orders من قاعدة jordanreg أو completion إلى حسابك.
3. طبّق الترحيل الإضافي على candidate فقط، وأنشئ مسار تشغيل استيراد مُراجع بهوية إدارية فعلية، بدل إزالة حواجز CLI الاختبار أو انتحال مدير fixture.
4. استورد CSV بالتجزئة الموثقة على candidate، قارن السجلات السابقة، وكرّر للتحقق من idempotency. أبقِ clinical labels وJO registration والمخزون والأسعار الحالية خارج الاستيراد.
5. راجع قرار إتاحة metadata غير المراجعة؛ الإصدار الحالي يمنع معاينة المصدر في production عمدًا. أي تغيير لهذا القيد يحتاج مراجعة حقوق وإعداد بيئة محدد، ولا يُحل بتسمية خدمة الهاتف test خلسة.
6. اختبر الدخول والطلبات والتذكيرات والدليل على staging HTTPS منفصلة بموافقتك دون قطع النفق الحالي.
7. بعد القبول، خطط نقلًا إضافيًا مضبوطًا إلى قاعدة الهاتف أو تبديل candidate بموافقة جديدة، مع رجوع موثق؛ لا ترحيل تلقائي.
8. حدّث APK كتحديث للحزمة نفسها والتوقيع نفسه، دون uninstall أو مسح بيانات. أبقِ عنوان HTTPS الحالي حتى يُعتمد backend متوافق. لو اختلف التوقيع، توقف؛ لا تحذف بيانات التطبيق لحل المشكلة.

## القيود والخطوة التالية

البيانات صالحة هيكليًا للاستيراد الداخلي؛ صحة المحتوى التنظيمي والدوائي وتحديث الأسعار وحقوق إعادة التوزيع ليست مثبتة. لا صور عبوات أو ترجمات طبية مصطنعة. لا تحويل لهذه الحزمة إلى مخزون صيدليات أو مبيعات. الخطوة التالية المفيدة هي مراجعة أصل البيانات وشروط إعادة استخدامها ثم الموافقة على candidate للهاتف؛ ليس تفعيل البيع أو النشر العام.
